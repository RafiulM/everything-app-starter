# everything-app-starter App Flow Document

## Onboarding and Sign-In/Sign-Up
A new user first lands on the public home screen of the application, which serves as a simple landing page describing the key features and benefits of the everything-app-starter. From here, the user clicks a prominent button labeled “Get Started” that brings them to the sign-up page at `/app/sign-up`. On the sign-up page, the user provides their email address, a secure password, and agrees to the terms of service. After clicking the “Create Account” button, they receive a confirmation email. Once they verify their email, the account is activated and the user is automatically signed in. To sign in on subsequent visits, the user goes to `/app/sign-in` and enters their registered email and password. A “Forgot Password” link on the sign-in page leads to `/app/forgot-password` where the user submits their email to receive a password reset link. Clicking the link in that email opens a secured reset form where they choose a new password. Successful password resets redirect the user back to the sign-in page. Signing out is accomplished by clicking the “Sign Out” button in the header, which terminates the session and returns the user to the public landing page.

## Main Dashboard or Home Page
After signing in, the user is taken to the main dashboard located at `/app/dashboard`. The dashboard loads a fixed header that shows the application name, a theme toggle, and the user’s profile avatar. Along the left side of the screen is a vertical navigation sidebar with links to the AI Chat section, AI Search section, AI Image Generation section, and Settings. The rest of the screen is the content area where feature pages slide in when navigated to. The dashboard uses consistent styling from Tailwind CSS and the shadcn/ui design system so that switching between sections feels seamless. From the dashboard, the user can click any navigation item to load that feature’s interface in the main content area.

## Detailed Feature Flows and Page Transitions
Once on the dashboard, the user can choose the Chat link, which navigates to `/app/chat`. The chat page displays a conversation history loaded from the database via Drizzle ORM. At the bottom, an input box lets the user type a new message. When they submit, the front end sends the message to the API endpoint at `/app/api/chat` along with the user’s session token. The server verifies the session with Better Auth, then passes the prompt to the `@ai-sdk`. As the AI model generates a response, the server streams the tokens back to the client in real time, and the UI renders the reply incrementally. When the full response arrives, both the user’s input and the AI’s answer are persisted into the `messages` table in PostgreSQL. If the user wants to attach a file, they click an attachment icon beside the input box, choose a file, and the file is uploaded to a storage service through a secure route at `/app/api/attachments`. Once uploaded, the file reference is included in the message record.

When the user clicks the Search link in the sidebar, the app navigates to `/app/search`. On this page, the user sees a search field at the top and a list of previous searches below. Entering a query and hitting “Search” sends it to `/app/api/search`, which uses `@ai-sdk` to find relevant information or summarize documents. Results are displayed in a scrollable panel. Each result can be saved to the user’s personal library by clicking a save icon, and those saved items are stored in a `saved_searches` table.

Selecting the Image Generation link brings the user to `/app/images`. Here they see an input area to describe the desired image and optional controls for style or resolution. Submitting this form calls `/app/api/images`, which uses the `@ai-sdk` to generate images. As images are created, thumbnails appear in a grid. Clicking a thumbnail opens a larger preview with a download button. Metadata about the image generation request and the resulting file URL are saved in an `images` table.

Throughout these feature flows, the app includes smooth page transitions managed by Next.js App Router. Navigating between sections updates the URL without a full page reload, and server components fetch only the data needed for each page.

## Settings and Account Management
The user accesses settings by clicking their avatar in the header and selecting “Settings,” which directs them to `/app/settings`. The default settings page shows personal information such as name and email, which can be edited and saved. Below that, theme preferences let the user switch between light and dark modes. Notification preferences allow toggling email alerts for chat transcripts or new feature announcements. If a billing or subscription model is later added, a “Billing” tab will appear under settings where the user can view invoices, update payment methods, or change subscription tiers. After making changes in any settings section, the user clicks “Save Changes,” and they see a confirmation message before being returned to the main settings overview. A “Back to Dashboard” link at the top lets the user return to their last visited feature page.

## Error States and Alternate Paths
If the user enters incorrect credentials on the sign-in page, an error message appears in red beneath the input fields explaining the issue. During sign-up, if the email is already registered, a warning explains that the user should sign in or reset their password. In any feature page, losing network connectivity shows a full-screen overlay with a message about offline status and a button to retry. If the AI API fails or returns an error, a contextual error message appears in the chat or search area, and the user can click “Try Again” to resend their request. Validation errors on settings forms highlight the specific fields that need correction. In the rare case of a server error, the application shows a generic “Something went wrong” page with a link to return to the dashboard or contact support.

## Conclusion and Overall App Journey
From discovering the landing page to signing up with email, the user enters a secure environment where they see an organized dashboard. They can navigate to AI Chat, AI Search, or AI Image Generation using a consistent sidebar interface. Each feature page follows a clear flow of input, server interaction, real-time response streaming, and data persistence. Through the Settings area, they manage their profile, preferences, and, in the future, billing. Built-in error handling ensures the user can recover from mistakes or connectivity issues. Overall, the everything-app-starter offers a unified, end-to-end experience enabling users to explore powerful AI features without ever leaving the cohesive application shell.
